§1

What the evidence supports

Read this before any number below.

Established, on this laptop

  • One API instance holds the platform-overhead gates through 500 req/s offered: p50 6.07 ms, p99 17.74 ms at step 5.
  • No unexpected errors and no correctness failure at any counted step.
  • Pool wait was 0.0 s and deadlocks 0 under load at every counted step.
  • The real API, killed at the money path's three dangerous moments, recovers with no second PSP call.

Not established

  • No capacity C and no instance count N. Laptop runs are previews; D53 moves both to the first Linux run.
  • Nothing about the 5,000 payments/s target. A laptop result can't be scaled to it.
  • The 500 payments/s milestone (D51) isn't met: it needs three valid 10-minute runs, and there are none.
  • No bottleneck is named. Step 6's dropped arrivals were a generator limit, and its p99 breach came from a run that was invalid on its count.
  • None of the D56 laptop verification has run, including two API instances behind nginx.
